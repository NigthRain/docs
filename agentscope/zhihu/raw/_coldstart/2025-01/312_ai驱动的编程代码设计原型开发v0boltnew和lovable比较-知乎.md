我喜欢的额外功能：
・选择元素功能：在 Lovable 中，你可以直接从预览中选择一个元素，并在聊天消息中引用它进行修改。这个不太常被提及的功能通过将你的反馈直接与 UI 元素关联，使迭代设计调整更加直观。
・自定义指令和知识库：Lovable 支持在项目中创建 “知识库”，你可以在其中定义项目特定的详细信息、功能或设计指南。这有助于保持一致性，并为人工智能提供上下文以获得更好的结果。
5、各工具的常见挑战
使用人工智能辅助工具构建 Web 应用程序有望简化开发流程，但用户在这些平台上经常会遇到一些特定的挑战。
・对人工智能准确性的依赖：“我让人工智能修复一个错误，结果它又引入了另外两个错误”。你很可能遇到过这种情况。所有工具都依赖人工智能对用户提示的理解。误解可能导致耗时的修正。例如，人工智能在解释复杂或模糊提示时的准确性可能会有所不同，这就需要清晰、详细的指令或后续的迭代。
・成本和资源限制：归根结底，如果你不运行本地模型，就需要有人为计算资源付费。这三个工具在基于令牌的使用限制方面都存在类似问题，这可能会影响在大型项目上快速迭代的能力，促使用户更快地转向付费计划。
・最终需要 “导出” 或 “脱离”：引导式工具在帮助你比以往更快地实现 MVP 方面非常出色，但它们存在我所提到的 “70% 问题”。你很可能会遇到一个复杂性阈值，此时转向在本地编辑代码（无论是使用传统编辑器手动编辑，还是使用 Cursor/Cline/Windsurf 等人工智能增强型编辑器）将是必要的。
这些挑战并不会削弱这些工具为 Web 开发带来的价值，但突出了用户需要准备好投入额外时间、资源或选择补充工具以实现目标的领域。
6、用例与建议
・用于组件的快速前端原型设计：v0 是最佳选择，它能提供快速且视觉吸引人的设计。不妨尝试一下它的全栈支持。
・用于快速全栈应用开发：Bolt 为前端和后端开发提供了一个全面的环境，生成速度最快。
・用于协作团队项目：Lovable 与 GitHub 的集成以及分支功能使其成为团队开发的理想选择。
・用于后端繁重的应用程序：Bolt 和 Lovable 都提供强大的后端集成，Lovable 在与 Supabase 等特定集成方面具有优势（Bolt 也一直在探索这方面）。
