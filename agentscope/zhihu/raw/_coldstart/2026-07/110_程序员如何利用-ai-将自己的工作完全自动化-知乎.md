# 程序员如何利用 AI 将自己的工作完全自动化? - 知乎

> 平凡 | 2026-07-22 17:56

来源: https://www.zhihu.com/question/594150259/answer/2063321600095674950?utm_medium=openapi_platform&utm_source=1a2112

第 2 次做，说明以后大概还会遇到。
等到第 3 次还在重复相同的操作，基本就能确定，这件事已经有了相对固定的输入和结果。继续人工做下去，无非就是拿人的时间，去填一个本可以由自动化程序完成的工作。
自动化收益 = 重复次数 × 单次节省时间 - 开发成本 - 长期维护成本
你可以这么理解，过程稳定的任务适合脚本，过程不稳定但结果容易检查的任务适合 Agent。
这里面提到的动作，倒并不一定是什么很复杂的大型项目。更多的，它可能只是每天检查一次服务日志，把异常信息整理出来；也可能是每周汇总 Git 提交和项目进度，写一份周报；或者收到需求以后，先生成接口代码、测试用例和文档，再检查有没有遗漏。
这些事情单独看都不复杂，甚至每次只占十几分钟。但它们会时不时地去打断你的正常或者正式工作，而且人在第 20 次做同一件事的时候，通常不会比第 3 次更认真。
所以说，这也是为什么一个动作如果重复了三次，或者未来还要再重复的话，就一定要考虑开始自动化。
对于以前来说，自动化是非常复杂的一件事情，你需要编排流程等等；但现在，这件事太简单不过了。
用我这套方法，其实做一个 Agent 或者是一个 workflow 的成本以及难度是非常低的。
你不需要先学会怎么做 Agent
过去做自动化，最难的是你必须提前把全盘过程想清楚。
先读取哪个文件，接着调用哪个接口，遇到异常怎么办，数据格式不对怎么处理，最后把结果存到哪里。人要先把一件事拆成足够精确的步骤，计算机才能按照这些步骤执行。所以很多人一听到“做一个 Agent”，还是会沿着过去的习惯去思考：我应该怎么设计工作流，怎么写提示词，怎么安排每一个节点，怎么告诉 AI 第一步做什么、第二步做什么。
但现在完全可以换一种做法。
Agent，你可以把它当成一个具有一定智能的人类，起码是大学甚至研究生水平的人类。
你不需要去主动设计流程，只需要提出你的目标，然后让他一步步去做。至于结果怎么样，你不需要一次到位，只需要一步步让他去迭代，直到你满意为止。所以在AI时代，Agent这东西最重要的已经不是技术方向，而是思维方式的转变，你得搞明白Agent其实是一套思维方式，而不是新的技术范式，自动化的方式并不是重构，而是一步步的迭代。
因此，搞懂 Agent 有些什么、能做什么、它的上限是什么，以及它的组合方式，是最重要的。
特别是 Agent 的核心——大模型，它所能支持的其实就是 Agent 的上限。
