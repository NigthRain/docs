# 大模型检索增强生成(RAG)有哪些好用的技巧? - 知乎

> 政企培训师朱华 | 2026-08-11 21:28

来源: https://www.zhihu.com/question/625481187/answer/2070622728495932681?utm_medium=openapi_platform&utm_source=1a2112

RAG是啥？Retrieval-Augmented Generation，翻译为“检索增强生成”‌，是当前大模型落地应用的核心技术框架。它的核心逻辑是让大模型在回答问题前，先从外部指定的知识库（企业文档、私有资料等）中检索相关片段，再基于这些真实资料生成答案，能有效解决大模型知识过时、凭空编造“幻觉”、缺少私有领域知识的痛点，广泛用于智能客服、企业知识库问答、合同分析等场景。要想部署可实际用于生产系统的大模型，必不可少要部署RAG系统。
常用的开源RAG系统有RAGFlow、LangChain、Llamaindex、Haystack、Dify。其中RAGFlow使用最简单，不需要编程，只需要把各种文档、资料丢个RAGFlow，它会自动读入文件、OCR识别（图片或PDF文件）、切片、向量化、词嵌入，不需要做任何编程。本着“宁可简单生决不复杂死”的理念，我决定先部署ragflow。
但是这简单的第二步，竟然让我走了整整一个星期，kill了windows11+wsl2（Windows Subsystem for Linux 2），又kill了RHEL10.2（Red Hat Enterprise Linux 10.2），把从安装操作系统到调试ragflow的整个过程跑了三遍。
多年以后，当我半躺在养老院的床上，眯着苍老昏花的眼睛，看着窗外斑驳陆离的阳光的时候，我可能会也可能不会偶尔想起2026年8月的这几个夏夜，我抓耳挠腮地跟N个系统就兼容性问题进行艰难搏斗后得到的关键感悟：对于叠床架屋般复杂的AI技术栈，兼容性简直就是最重要的命根子。
回顾三次安装AI应用系统的过程，我很纳闷我到底做了什么，竟然重复了历届足球世界杯上阿根廷队和意大利队的经历：开头顺利的最后却栽了，开头不顺的最后反而很顺。
第一次安装旅程：我决定能偷懒就决不瞎操操（后来发现这个理念把我带沟里了），我用本本自带的windows11，安装wsl2（Windows Subsystem for Linux 2），超丝滑。
安装miniconda，没啥问题。
安装vs code（Visual Studio Code），虽然设定python解释器时折腾了一会，但也很快解决了。
再安装ollama，很顺利。
安装deepseek-r1:8b，顺利。
到最后安装ragflow时，出问题了。
ragflow安装了一堆服务，mysql、elasticsearch…都能成功启动，但最关键的服务ragflow反复启动反复崩溃……折腾了我一晚上后我也崩溃了，后来发现是windows wsl的原因，wsl其实是阉割版Linux，ragflow需要的一些后台调用模式被屏蔽了…..加上系统没部署在docker了，第二天我一咬牙加一跺脚，决定格了windows11+wsl2，直接上Linux。
