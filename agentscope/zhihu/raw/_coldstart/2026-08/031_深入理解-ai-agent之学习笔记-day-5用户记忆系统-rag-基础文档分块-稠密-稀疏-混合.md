Day 5：用户记忆系统 + RAG 基础（文档分块 → 稠密 → 稀疏 → 混合检索）
目标
Agent 怎么在对话结束后仍然记住用户（用户记忆系统），以及 Agent 怎么从外部知识库找到需要的信息（RAG 基础管道）。这两件事共用同一套底层技术。
核心知识点
一、为什么需要跨会话记忆？
Day 2-4 学的都是"单次会话内的上下文管理"——会话结束，一切归零。但真正的 Agent 需要：
・用户记忆（个体）：记住你的偏好、习惯、历史 → 让 Agent 成为"懂你的助手"
・知识库（群体）：共享的行业法规、公司文档、技术手册 → 让 Agent 成为"领域专家"
两者解决同一个问题，只是尺度不同：一个关注个体，一个关注群体。它们共用向量检索、知识压缩等底层技术。
二、用户记忆：不是记流水账，是建预测模型
核心洞察：记忆不是记录用户说过的每一句话，而是通过持续交互，在脑海中逐渐形成关于对方的模型——他的爱好、习惯和价值观。

三、记忆评估：三层次框架
这是本章的标尺，后文所有实验都用它衡量：
层次	能力要求	例子
第一层：基础回忆	准确存储和检索用户直接提供的结构化信息	“我的会员号是12345” → 精确返回
第二层：多会话检索	从多个不同会话中检索相关信息并推理判断	用户有两辆车，说"帮我车预约保养" → 找出全部两辆车，主动问哪辆
第三层：主动服务	综合跨会话信息，提供预见性帮助	订国际航班时主动关联数月前的护照信息，发现即将过期并预警
第三层是最难的——要求系统同时握有"全局概览"和"精确细节"。
四、记忆的三套分类体系（别搞混！）
分类体系	回答的问题	具体类别
记忆层次	存在哪里？	轨迹（当前会话）、用户长期记忆（跨会话）、业务状态（任务阶段）
存储格式	怎么存？	Simple Notes、Enhanced Notes、JSON Cards、Advanced JSON Cards
认知类型	存什么？	情景记忆（具体事件）、语义记忆（一般知识）、程序记忆（行为流程）
三套体系是正交的——可以自由组合。
比如"用户偏好靠窗座位"是语义记忆，可以用 Simple Notes 格式存在用户长期记忆中。
