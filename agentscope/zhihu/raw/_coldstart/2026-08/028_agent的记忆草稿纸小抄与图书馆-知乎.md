# Agent的记忆:草稿纸、小抄与图书馆 - 知乎

> 为啥啊凭啥啊 | 2026-08-11 15:13

新会话的 messages.json 是全新的，但Agent依然答得出来——因为信息不在草稿纸上，在跨会话的小抄里。
到这里，还有一层更深的追问：小抄里到底记什么？
如果什么都往小抄上写，它会膨胀成一本字典——你把每天的细节都抄进去，每次对话都带上，既浪费上下文篇幅（草稿纸越来越挤），又淹没了真正重要的结论。真正的智能，不在于”能记多少”，而在于知道”记什么”和”不记什么”。
在ARF中，我给出的拟人解法：记什么，是Agent主动判断的，我只给它一个用来管理记忆的工具包。 它不是把对话像抄录一样复制，而是在对话中按照我写在write_user_memory 工具中的任务提示词来筛选出”这值得记住”，并主动调用工具存下。
这本质上还是工具调用！回想第二篇：一切能提供能力的都是工具。记忆也不例外：Agent调用 write_user_memory，和调用 read_file 没有结构差异，只不过读写目标是那张小抄。

(工程上的这部分的策略有很多，读者感兴趣的话，我之后可以进行深入的专题梳理介绍)
会话记忆 vs 全局记忆：一张表厘清两层结构
三类记忆，各管一摊：
类比维度	会话记忆（短期上下文）	全局记忆（固定注入）	外挂知识库（按需检索）
本质	当前情景的动态工作记忆	关于用户的固定画像与偏好	外部沉淀的事实与文档库
类比物	📄 一张草稿纸	📒 小抄（压缩便签）	📚 图书馆
读取时机	每次推理自动带入上下文	每次对话固定注入（作为系统提示词的一部分）	根据当前问题按需检索（RAG）
写入方式	自动追加，滚动更新	主动提炼，人工或Agent写入	预先批量导入或增量更新
生命周期	会话结束 → 立即清空	跨会话永久保存，相对固定	长期保存，持续维护更新
典型场景	“刚才工具返回的那个IP地址是什么？”	“我叫良子，回答问题喜欢简洁直接”	“公司去年的财务报销制度是什么？”
风险	上下文溢出，早期信息被截断	记错偏好，形成固定偏见	检索不准，答非所问
三者各司其职，对应三种完全不同的”记住”逻辑：
草稿纸（会话记忆）管”接得上”——知道刚才聊到哪、刚才工具返回了什么，确保对话连贯。只活在当前会话里，会话结束就丢掉。
小抄（全局记忆）管”记得住”——知道你是谁、你喜欢什么、关键结论是什么。
允许你带，但小抄也占草稿纸（上下文窗口）的空间，所以必须把大量信息压缩成最小可用的条目。
每次新对话都会作为系统提示词的一部分固定注入——它不占”搜索成本”，但占固定的上下文篇幅。
