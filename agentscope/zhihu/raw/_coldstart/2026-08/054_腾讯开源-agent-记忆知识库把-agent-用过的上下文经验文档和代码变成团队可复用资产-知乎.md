“Flutter Android 构建失败排查”可以包含触发条件、检查 Gradle 和 AGP 版本的步骤、需要读取的配置文件、常见错误分支、允许执行的诊断命令，以及最后用哪些构建和测试结果验收。
这样下次另一个 Agent 遇到相似问题，就可以检索并加载这个 Skill，直接沿着已经验证过的流程执行。个人 Skill 默认保持私有，审核后才进入团队共享范围，还可以只分配给特定 Agent。
LLM-Wiki 接收上传文件或远程文档，把内容加工成结构化页面，然后这里可以维护原始文件、页面、全文搜索、页面链接、图谱节点、边和社区。
OpenAPI 提供创建、异步导入、读取原始文件、读写页面、搜索和图谱查询等接口。
Wiki 当前的搜索说明以 BM25 全文检索为主，所以不能把它描述成纯向量知识库，它更适合产品说明、设计文档、运维手册和项目规范，Agent 可以先搜索入口页面，再沿着链接图继续阅读相关主题。
CodeGraph 处理 Git 仓库，完成克隆和索引后，Agent 可以搜索文件与符号，查看某个函数的调用者和被调用者，沿代码关系向外探索，并执行影响分析。
比如修改一个共享缓存接口前，Coder Agent 可以先查哪些模块调用它，Reviewer Agent 再根据影响路径检查测试覆盖和兼容风险。
实际上这个模块用了开源 @colbymchenry/codegraph 项目的代码和设计
而 Wiki 和 CodeGraph 都支持状态查询和同步流程：
・如果仓库发生变化，可以重新同步 CodeGraph
・如果文档发生变化后，可以再次执行 Wiki 导入和页面更新
最后，按照官方说法，在添加专用角色记忆后，角色一致性从 48% 跃升至 76%。
然后在压缩会话中过时的上下文场景，减少了 61% 的令牌使用量，给 Agnet 提供结构化的任务地图，大大降低了他们在 30 多个步骤的工作流程中迷失率。
其他比如 WideSearch 这种大范围信息搜集，例如查找大量公司、职位、产品或公开数据，还需要保证结果尽可能完整、准确和结构化，接入插件后 ：
・OpenClaw 成功率从 33% 提高到 50%，增加了 17 个百分点
・Token 从 2.2131 亿降到 8564 万，减少约 61.3%
也就是符号记忆对于搜索日志特别密集的任务价值最大，大量网页结果被移出上下文，Agent 只保留 Mermaid 状态图和索引，需要核对时再按 node_id 回查原始内容。
