对应第一个月计划第 3 周第 4 天：区分确定性 pipeline 与自主 Agent，理解 LangGraph 或自研状态图的节点、边、状态和恢复机制。
建议投入：4～5 小时。当天交付：一个“检索 → 总结 → 结构化输出”的三节点流水线，可选择 LangGraph 或自研状态图实现。
一、今天完成后要达到什么程度
你应当能够：
1.判断任务适合确定性 pipeline、条件状态图还是自主 Agent。
2.为每个节点定义严格输入、输出、错误和副作用。
3.用共享状态串联检索、总结和结构化输出三个节点。
4.实现条件边、失败分支、重试上限和最终状态。
5.让检索为空时跳过无意义的总结调用。
6.使节点可单独测试、可观察，并能从安全检查点恢复。
7.解释框架编排与自研状态图的取舍。
二、必须掌握的知识点
1. Pipeline 与 Agent 的差异
确定性 pipeline：
・步骤和顺序预先确定；
・每个节点职责稳定；
・易于测试、审计和估算成本；
・适合合规、批处理和固定业务流程。
自主 Agent：
・模型根据观察选择下一动作；
・能处理开放式任务和不确定路径；
・更灵活，但终止、成本和权限更难控制。
选择原则：
两者可以混合：确定性状态图中的某个受限节点可运行短 Agent loop。
2. 状态图四要素
边应由可解释条件驱动，例如 retrieval_status == "empty"，而不是依赖模糊自然语言。
3. 三节点流水线
最终节点只负责验证和格式化，不应偷偷重新检索或添加新事实。
4. 节点契约
每个节点要写清：
・输入字段；
・输出字段；
・前置条件；
・成功状态；
・可重试错误；
・不可重试错误；
・是否有副作用；
・超时和日志字段。
节点契约比“整个链能跑”更重要，因为故障需要定位到具体边界。
5. 检查点与幂等
检查点可支持恢复，但不能盲目保存敏感完整状态。恢复时需要确认：
・工作流版本一致；
・输入和权限仍有效；
・已完成的副作用是否可重复；
・检查点是否过期；
・是否需要从某节点重新执行。
三、一步步完成今天的任务
第 0 步：确定实现路线（约 20 分钟）
二选一：
・自研：用 Python 函数、枚举和显式调度器；
・LangGraph：用 StateGraph 表达节点和条件边。
初学建议先画状态图和节点契约，再使用框架。框架 API 以安装版本的官方文档为准。
